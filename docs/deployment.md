# Deployment

On Ubuntu, install Docker and point the domain's A/AAAA records at the server. Copy `.env.example` to an untracked `.env`, set a random `JWT_SECRET` and strong `POSTGRES_PASSWORD` (neither has a fallback secret), `DOMAIN`, and replace the extension-ID placeholder in `CORS_ORIGINS` with the trusted unpacked/installed extension ID. After DNS resolves, run `set -a; source .env; set +a; COMPOSE_PROJECT_NAME=know-prod ./deployment/preflight.sh`, then `COMPOSE_PROJECT_NAME=know-prod docker compose up -d --build` or use `./scripts/rebuild.sh`. Development uses a separate `know-dev` Compose project and does not change the production containers or volumes. The preflight rejects placeholder secrets, local/example domains, missing production CORS origin, unresolved DNS, invalid Compose interpolation, and invalid Caddy configuration. Compose passes `DOMAIN` into Caddy; when it is omitted for local development, Caddy listens on its local `:80` fallback. Requests for a non-local configured domain on port 80 are redirected to HTTPS; the `localhost` fallback remains available for local development and smoke tests. The convenience HTTP port 3000 is bound to loopback only for local access; only ports 80 and 443 are publicly published. The default CORS policy allows only the local web client; extension origins must be opted in through configuration. The production web build uses the same-origin `/api/v1` proxy by default; `VITE_API_URL` is only needed for a separately hosted API. To enable Google sign-in, set `GOOGLE_CLIENT_ID` to the OAuth 2.0 Web client ID configured for the deployed domain; the same value is used to verify Google ID-token audiences on the API and render the web sign-in button. Leave it blank to disable that optional button. Caddy obtains and renews certificates automatically. PostgreSQL and the API remain private.

The API exposes `/actuator/health`, and Compose waits for PostgreSQL health before starting it. The public Caddy proxy has its own HTTPS health check and emits baseline `nosniff`, frame-denial, strict-origin referrer, CSP, and restrictive Permissions-Policy headers. Compose keeps each service's JSON logs bounded to three 10 MB files; inspect them with `docker compose logs --tail=200 api` (or `db`, `web`, or `proxy`) and forward them to the host's normal log collection if required. Back up with `./deployment/backup.sh` (or pass an explicit output filename); the script refuses to overwrite an existing file. Restore into a separate database first with `psql` and verify the migration/data contents before relying on a backup. Keep the named database volume and Caddy data volume on persistent storage.
