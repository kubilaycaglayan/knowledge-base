# Deployment

On Ubuntu, install Docker and point the domain's A/AAAA records at the server. Copy `.env.example` to an untracked `.env`, set a random `JWT_SECRET` and strong `POSTGRES_PASSWORD` (neither has a fallback secret), `DOMAIN`, and `CORS_ORIGINS`, then run `docker compose up -d --build`. The production web build uses the same-origin `/api/v1` proxy by default; `VITE_API_URL` is only needed for a separately hosted API. Caddy obtains and renews certificates automatically. Only ports 80 and 443 are published; PostgreSQL and the API remain private.

The API exposes `/actuator/health`, and Compose waits for PostgreSQL health before starting it. The public Caddy proxy emits baseline `nosniff`, frame-denial, strict-origin referrer, CSP, and restrictive Permissions-Policy headers. Back up with `./deployment/backup.sh` (or pass an explicit output filename); the script refuses to overwrite an existing file. Restore into a separate database first with `psql` and verify the migration/data contents before relying on a backup. Keep the named database volume and Caddy data volume on persistent storage.
