# OTOTEST-01 — Extension and cross-client feature map

**Source revision:** `2e0e4450` (OTOTEST-05 extension gate update).
**Source review:** `chrome-extension/wxt.config.ts`, `chrome-extension/entrypoints/`, popup/options source and tests, `.github/workflows/verify.yml`, `scripts/run-smoke-tests.sh`; reviewed 2026-10-11.
**Inventory reviewer:** Codex source inventory; project owner confirmed desktop-only extension support on 2026-10-09.
**Inventory owner:** Knowledge Base maintainers; maintain permission and cross-client evidence and own support decisions.
**Execution commands:** `(cd frontend && npx playwright install --with-deps chromium) && ./scripts/run-extension-browser-e2e.sh` (isolated packaged-browser runner); required CI gate: `verify / web-and-extension` — Run packaged extension browser acceptance.

The extension's manifest is generated by WXT from `wxt.config.ts`; a checked-in `manifest.json` is not the source of truth. The verification workflow inspects the built manifest for overly broad host permissions and runs the packaged browser journey in a fresh temporary profile. Node tests establish module behavior; browser-native permission prompt rendering and live provider flows remain manual/unverified gaps. Unresolved gaps and support decisions are owned by Knowledge Base maintainers.

Each entrypoint/permission row, feature-domain row, and ordered journey has
one evidence status. Feature domains and journeys are `gap` while their final
column describes an unproven flow. Entrypoint statuses classify the row's
whole listed behavior: `covered` rows have no listed gap, `manual` rows link
the exact pending procedure, and unsupported surfaces retain their scope
rationale. The owner in this file owns remaining gaps and manual checks.

EXT-01 through EXT-09 map to the extension criteria below. XCLIENT-01 through XCLIENT-04 and MERGE-01 through MERGE-10 map to the cross-client journey table and feature map. The packaged desktop Chromium journey now has local evidence; remaining live-provider and permission-prompt limitations are identified by row.

## Ranked inventory gaps for follow-up milestones

Rank is risk-based from the roadmap criteria; this is backlog input, not a claim that these behaviors are untested everywhere.

1. **Ownership and persisted mutations:** map missing positive endpoint assertions, direct and referenced foreign IDs, delete/archive effects and state readback. Feed OTOTEST-02.
2. **Timer invariant and aliases:** prove canonical and ID routes have equivalent stop/cancel behavior, server-derived duration, concurrent start conflict and cross-client recovery. Feed OTOTEST-02/04.
3. **Board and All boards contract:** map every operation, cursor/order behavior, transaction rollback, stale card conflict, status/card archival and Gantt range edges. Feed OTOTEST-02.
4. **Route/deep-link/history behavior:** cover redirect, query restoration, Back/Forward, logged-out direct-load and missing/foreign resource behavior in a browser. Feed OTOTEST-03.
5. **Visible controls and accessible alternatives:** map action-level assertions for dialogs, repeated row actions, keyboard/touch alternatives, focus/live feedback and error recovery. Feed OTOTEST-03.
6. **Desktop Chrome extension runtime:** add installed-extension coverage for popup/options, worker messages, permission boundaries and Clockify import handoff. Feed OTOTEST-04.
7. **Mobile Chrome:** treat web app as distinct from desktop extension, and record manual/browser evidence for coarse pointer, viewport/keyboard, date range and board interactions. Feed OTOTEST-03/04.

## Exclusions and source update rule

Native iOS is excluded because the repository roadmap says the app is inactive and there are no current iOS release gates; revisit only when it becomes supported. `/development` is temporary label-picker tooling, remains directly addressable, and is excluded from authenticated navigation and supported-route completeness. The project owner confirmed that the Chrome extension is supported on desktop Chrome only and unsupported on mobile Chrome. The responsive web app is the supported mobile Chrome surface. When a manifest entrypoint, permission, route, API operation or workflow changes, update the corresponding matrix in the same change.
