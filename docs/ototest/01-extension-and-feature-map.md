The extension's manifest is generated by WXT from `wxt.config.ts`; a checked-in `manifest.json` is not the source of truth. The verification workflow inspects the built manifest for overly broad host permissions. Extension UI tests run under Node and do not establish an installed Chrome journey.

## Ranked inventory gaps for follow-up milestones

Rank is risk-based from the roadmap criteria; this is backlog input, not a claim that these behaviors are untested everywhere.

1. **Ownership and persisted mutations:** map missing positive endpoint assertions, direct and referenced foreign IDs, delete/archive effects and state readback. Feed OTOTEST-02.
2. **Timer invariant and aliases:** prove canonical and ID routes have equivalent stop/cancel behavior, server-derived duration, concurrent start conflict and cross-client recovery. Feed OTOTEST-02/04.
3. **Board and All boards contract:** map every operation, cursor/order behavior, transaction rollback, stale card conflict, status/card archival and Gantt range edges. Feed OTOTEST-02.
4. **Route/deep-link/history behavior:** cover redirect, query restoration, Back/Forward, logged-out direct-load and missing/foreign resource behavior in a browser. Feed OTOTEST-03.
5. **Visible controls and accessible alternatives:** map action-level assertions for dialogs, repeated row actions, keyboard/touch alternatives, focus/live feedback and error recovery. Feed OTOTEST-03.
6. **Desktop Chrome extension runtime:** add installed-extension coverage for popup/options, worker messages, permission boundaries and Clockify import handoff. Feed OTOTEST-04.
7. **Mobile Chrome:** treat web app as distinct from desktop extension, and record manual/browser evidence for coarse pointer, viewport/keyboard, date range and board interactions. Feed OTOTEST-03/04.

## Exclusions and source update rule

Native iOS is excluded because the repository roadmap says the app is inactive and there are no current iOS release gates; revisit only when it becomes supported. `/development` is temporary label-picker tooling, remains directly addressable, and is excluded from authenticated navigation and supported-route completeness. Mobile Chrome extension use is unsupported in the current product configuration; mobile Chrome web use remains its own surface. When a manifest entrypoint, permission, route, API operation or workflow changes, update the corresponding matrix in the same change.
