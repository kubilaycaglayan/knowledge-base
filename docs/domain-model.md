# Domain model

`User` owns paths, notes, logs, and reusable labels. The `logs` table stores untitled owner-scoped text with an explicit occurrence timestamp and optimistic version. Log labels are stored in `log_label`; users can assign any of their reusable labels that has the `LOG` scope. The `labels` catalog stores one user-owned label per name, while `label_scope` controls whether it is available to notes, calendar records, time entries, or logs. Time entries preserve work duration with explicit `WEB`, `IOS`, `CHROME_EXTENSION`, `MANUAL`, or `IMPORT` sources and can carry zero or more scoped labels. Notes are standalone knowledge records that may target one path, activity, or time entry, store rich Tiptap JSON plus a searchable plain-text projection, connect to reusable labels through `note_label`, and use a 30-day soft-delete archive before permanent cleanup. Activities describe what happened, notes preserve knowledge, and a running timer is server-owned with one active timer per user enforced by the service and a PostgreSQL partial unique index. Optional `daily_record` entries preserve a selected calendar date’s note and reusable `daily_record_label` assignments; portions are retained only for reportable calendar events and are not work duration. Labels can be managed from the Labels page without duplicating a label for each context. Boards hold statuses and cards; every path owns exactly one board (`boards.path_id`, unique, deleted with the path) that follows the path's name and lifecycle and whose cards always belong to that path, while custom boards are user-named, pinnable, and manually ordered. A path board's `hidden` flag only removes its tab; its cards are kept.
