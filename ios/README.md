# Know iOS client

This is a native SwiftUI executable target, not a web wrapper. Open `Package.swift` in Xcode on macOS, select an iOS simulator/device, and configure the `KNOW_API_URL` scheme environment variable to the shared API URL. The package also declares macOS 14 for host-side Swift test/build validation; the client uses Keychain for the JWT and the same `/api/v1` endpoints as the web client and extension.

Implemented daily flows include authentication, dashboard statistics, path creation, item creation with active-path selection, item details, progress updates, item notes, timeline refresh, resource-aware timer start/stop, and dashboard timer targeting by active path and item. The API client and app model accept injected transports, retry transient GET/HEAD failures once without replaying mutations, and report an offline state so response decoding, authentication expiry, and reconnection behavior can be unit tested. Critical SwiftUI controls expose stable accessibility identifiers, and `KnowUITests/KnowUITests.swift` contains the initial authentication UI test source. `project.yml` defines the iOS app, unit-test, and UI-test targets; generate them with XcodeGen before running the XCUITest scheme. The Linux development environment cannot compile SwiftUI or execute XCUITest, while repository CI generates the targets and runs them on macOS.

On macOS, run `brew install xcodegen && xcodegen generate --spec project.yml`, then open `Know.xcodeproj` or run the `xcodebuild` commands from CI to build and execute the unit/UI-test scheme. CI selects the first available iPhone simulator on the runner. The `-ui-testing-authenticated` launch argument is an isolated XCUITest fixture only; it seeds temporary in-memory paths/items and never runs in normal launches.
